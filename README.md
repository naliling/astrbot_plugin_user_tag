# Humanoid Core · 人形化伴侣插件

一个有自己的时间、会累会饿会犯困、情绪会积累也会放不下的 AI 身体引擎。

**这个插件负责给 AI 一具身体，不负责替 AI 说话。** 它把状态编译成模型能「感觉到」的
背景，说什么、说不说、什么时候说，都交给模型自己判断（或者交给
[自主拟人社交](#她与自主拟人社交是什么关系) 那个插件）。

---

## 它是什么

**身体（生理层 soma）**——一组会随时间自行变化的量，不只是一个「精力」标量：

- **睡眠压力**：醒着就一直攒，睡着才消解；生物钟低谷时段攒得更快
- **睡眠债**：该睡的时候醒着就欠下，靠睡觉还；欠着的时候第二天精力起点更低
- **昼夜节律**：凌晨是主低谷，午后有次低谷，傍晚最清醒——不是「23 点后算夜里」这种硬窗口
- **精力**：由日程时段驱动（工作/外出只减，睡眠/休息才回升），并被身体封顶
- **唤醒度**：与精力是两根轴。「很累但精神还有点亢、安静不下来」是可能的状态
- **饥饿**：距上次进食越久越饿；日程里写着用餐的时段会把这一顿吃掉
- **躯体不适**：久坐的肩颈发僵、天气的冷与热、生理周期的坠痛，合成一句「身上不太舒服」
- **社交能量 / 想找人说说话**：前者是聊累了，后者是独处攒出来的心思

时间自己流动：插件有一个每 60 秒一次的身体 tick，**不依赖有没有人发消息**。没人聊天的
那十几个小时里她照样会困、会饿、会坐太久。停机几天后重启，会按离线时长把身体补算回来
（上限 72 小时，不会攒出离谱数值）。

**心境与关系**

- 好感度、亲近欲、攻击性三个维度，各自有基线与衰减，随对话变化
- 心情标签（如「有点疲惫，开心，亲切」）——v2.11.x 起 README 一直在宣传它，但那时
  只有读没有写，实际永远是空的；v2.14 起真的会写
- 情绪日志：记住让她情绪波动的时刻
- 过程历史：刚做完什么，会作为「最近做过」提供给模型
- 对方离开前说的最后一句话，隔了一阵回来时能接得上

**生活与环境**

- 每天有不一样的日程，由大模型在后台生成；生成期间用按日期轮换的内置模板，不卡聊天
- 持续进行的生活过程 + 过程内部阶段（一个几十分钟的过程里也会自然换小动作）
- 天气（OpenWeather）、时区/星期/节日、可设定的称呼
- 多角色完全隔离：每个机器人一份独立的身体、日程、心境，以及**每个角色独立的用户昵称表**
- 三档注入程度 `full` / `low` / `mood_only`，v2.14 起三档是真的不一样

## 她与「自主拟人社交」是什么关系

| | 人形化伴侣插件（这里） | 自主拟人社交 |
|---|---|---|
| 管什么 | 她此刻是什么样：身体、心境、日程、天气、和谁的关系 | 现在该不该开口、找谁、说什么更像人 |
| 会不会主动发消息 | **不会** | 会 |
| 数据流向 | 导出契约快照 | 读契约，写回信号 |

两个插件一起用时不需要额外配置：

- **Core → Social**：`state.json` 里每个角色的 `self.contract`，带 `v` 版本号，字段只加
  不改。里面是各条身体轴、第一人称体感短句、说话形式倾向（`max_chars`、提问倾向），
  以及「她多想找人说话」这个量。社交层拿它当念头模型的燃料，而不是自己从精力标量硬猜。
- **Social → Core**：社交层往**自己**的目录里写一个 `humanoid_signals.json`（刚主动找过
  谁、被连着冷落几次）。Core 只读它，超过 15 分钟不采信。两边各写各的文件，不存在两个
  插件抢写同一个文件的问题。

拿不到契约时（没装社交层、或 Core 太老没有 contract 段），社交层会退回读旧字段，功能
不中断。`/拟人诊断` 会明确告诉你联动到底有没有生效。

## 状态是怎么交给模型的

以前是把状态拼成一行标签卡塞进用户消息：

```
【拟人状态】日期2026-09-13·清晨；地点北京；精力状态一般，语气平和；情绪调皮；社交能量低。
```

模型看到的是一堆**数据**，所以只能再补一句「禁止提及任何具体数据」去堵它的复述冲动。
现在编译成三段，并且按显著度门控：

```
【此刻】只有你和TA两个人在聊；2026-09-13 深夜；你在北京；这边 天气：晴，气温 24℃。
【我的感觉】眼皮很沉，句子不想写长，脑子转不动；坐太久了，肩颈发僵。
【这一轮】话说得短，别超过40字；这一轮不追问，先接住对方说的。
【对TA】对TA的感觉：依恋（语气柔和，略带撒娇）；你管TA叫小娜。
```

三个要点：

1. **给体感，不给数值。** 「精力 34」不会让模型把话说短；「眼皮很沉，句子不想写长」会。
2. **身体改变的是说话形式，不只是语气。** `form_policy` 会给出这一轮的字数上限、提问
   倾向、适不适合长回复——这比「语气慵懒」可靠得多，因为它不依赖模型自觉。
3. **想的比说的多。** 每条轴都有显著度，低于门槛的一律不注入。默认档最多两句体感。
   真人不会每条消息都报备自己的身体。

## 日程是怎么来的

每天第一次需要日程时，插件在**后台**向模型请求一份当天安排；请求期间聊天照常，用的是
按日期确定性轮换的内置模板，拿到结果后自动替换。

候选链：`首选模型 → 备用模型 → 全局默认模型 → 内置日程模板`。找不到、超时、报错三种
失败等价处理；失败的模型进入冷却期（默认 30 分钟）内被跳过，成功一次立即解除；整条链
都失败则按退避间隔重试。**日程生成失败不会阻止第二天重新尝试。**

一个值得知道的细节：**失败退避以前会被永久绕过**——`today_date` 只在生成成功时写入，
模型一直不可用时它永远不是今天，于是每个后台周期都被当成「跨天」而绕过冷却，变成每
30 秒一次永久重试。v2.14 起会记住「今天试过」，退避真正生效。

## 身体是怎么变的

日程里每个时段带一个 `energy_rate`（每分钟精力变化）。负值时段只减，非负时段才回升；
生理周期给消耗和恢复各乘一个阶段系数。此外：

- **睡眠债**压低新一天的精力起点（欠得越多起得越低，最低到 5 折）
- **躯体不适**放大消耗、并给精力设一个当天封顶——欠着一身债的人，就算日程写着整个
  下午都在休息也回不满
- **吃饭**由日程里的用餐时段决定，一顿就把饥饿归零
- **久坐**在日程写着运动/通勤/家务的时段会被打断
- **天气**的冷热计入躯体不适（需要天气可用）

想调曲线：`energy_decay_rate`（全局速度倍率）、`energy_natural_recovery_per_minute`
（休息时段的额外恢复）、`sleep_need_hours`、`meal_interval_hours`、
`sitting_discomfort_minutes`、`desire_refill_hours`。

## 作息：夜间窗口、日程、一晚睡多久

「她几点起」以前有三个地方都能回答，而它们互相不认识：夜间窗口说 5 点，日程模板说
7:30，`sleep_need_hours` 说 8 小时（而且根本没人读它）。v2.14.2 把三者接成一条链：

| 层 | 管什么 | 不管什么 |
|---|---|---|
| `night_start_hour` → `night_end_hour` | **生物钟夜**：入睡点与起床点、昼夜低谷的位置、睡眠债的记账边界、夜间语气 | 不直接决定她此刻在不在睡 |
| 今日日程的睡眠段 | **她实际在睡的那几个小时**（`is_sleep_time` 只认事件名） | —— |
| `sleep_need_hours` | 一晚睡多久算睡饱：困意清除速率 = `100/本值` 每小时；熬夜欠的债按 `本值/窗口长度` 放大 | 不再参与醒来时的记账 |

两边由 **`schedule_follow_night_window`**（默认开）对齐：日程 prompt 里写清她几点上床、
几点起，模型不听话时安装前还会把睡眠区间按夜间窗口重切一次，内置模板同样对齐。所以
把 `night_end_hour` 设成 6，她 6 点就真的已经起了床。

窗口比 `sleep_need_hours` 短（例如 23:00→05:00 配 8 小时）是**真的会出问题的配置**：
一夜睡不满，早上带着没清完的困意起床，下午就蔫。`/拟人诊断` 的【作息】会直接标出来，
想睡够 8 小时就把起床点推到 07:00。

夜间语气仍由 `night_mode_force_sleep` 分强弱，**这两档都是真的生效**（v2.13.2 里这个配置项没有任何代码读）：

| | 关（默认） | 开 |
|---|---|---|
| 深睡段 / 正在睡 | 刚被吵醒，迷迷糊糊、句子断续，说不长 | 只回一句「我现在需要休息，明天再聊吧」 |
| 浅睡段 | 夜里慵懒，说话轻、短 | 简短回应并提一句想睡了 |

配合身体的字数上限一起起作用：真的在睡的时候，`form_policy` 会把这一轮压到 20 字以内。
这些都是写进上下文的语气指导——插件不会拦下你的消息，最终怎么回还是模型决定。

关掉 `night_mode_enabled` 意味着：不再有夜间语气、不再记睡眠债，而且**没有日程时她
永远不算在睡**（以前只关掉语气、债却照记，两处语义不一致）。

## 上次对话间隔

`last_interaction_threshold_minutes` 默认 5 分钟：超过这个时间，插件才开始在上下文里
注入间隔信息。算的是**上一次触发回复**到现在，所以纯指令消息和没唤醒它的群消息不会
重置计时。第一次对话没有历史，不会出现这段提示。

`last_interaction_mode` 两档（v2.14 起真的区分）：

| 模式 | 行为 |
|---|---|
| `simple` | 只说「对方隔了约 2～6 小时重新出现」这类氛围描述 |
| `with_last_msg` | 同上，并附上 TA 离开前说的最后一句话（默认） |

间隔事件是**一次性**的：只在「回来这一轮」出现，下一条用户消息开始就清掉，不会在一小时
里每条消息都重复注入。

## 情绪是怎么算的

好感度、亲近欲、攻击性三个维度，每条消息先过一遍本地词典规则；开着
`mood_use_llm_for_delta`（默认开）时，每 `mood_llm_interval_messages` 条消息（默认 5）
再叫模型分析一次，两个结果加权融合。计数从 0 起算，所以新面孔的第一条消息只走本地规则。

- 精力与生理周期会调制情绪变化的幅度（排卵期更敏感，经期正负都被放大）
- 心情标签在每次情绪更新时刷新（`mood_tag_enabled`）
- 群聊默认不参与情绪：`mood_enabled_in_group` 关着时群消息不做情绪分析与衰减，但发言过
  的成员仍会记录聊天间隔与上一条消息（群聊里的「知道好久没聊了」靠它）
- 情绪模型的失败冷却与日程的冷却各自记账，即使两边用同一个模型也互不影响
- `mood_data_retention_days` 默认 7 天：超过 7 天没说话的用户，情绪档案会被清掉，好感度
  回到初始值；**用户自己设定的昵称保留**。设为 0 = 永不清理

## 关键配置项

| `schedule_llm_timeout_seconds` | `60` | 单次生成超时 |

| `schedule_provider_cooldown_minutes` | `30` | 日程模型失败后的冷却 |
| `use_llm_schedule` | `true` | 关掉只用内置模板 |
| `mood_use_llm_for_delta` | `true` | 是否用模型分析情绪变化 |
| `mood_llm_interval_messages` | `5` | 每多少条消息用模型分析一次 |

完整列表见 `_conf_schema.json`，每一项在 WebUI 里都带说明。

**升级注意**：AstrBot 更新插件配置时只补缺失项、从不覆盖已有值，所以调默认值对老用户
是无效的。v2.14 首次启动会把「仍然等于旧默认值」的 `weather_location`（旧版写死
`Heyuan,CN`）提升一次并写回配置文件——只在她已经改过所在城市的情况下做，她自己填的
城市一律不碰；同时留一个标记文件，之后不会再动。

## 代码结构

```
main.py                  # AstrBot 适配层：指令注册 + 事件解包 + LLM 请求注入
humanoid/
  config.py              # 唯一的默认值来源 + 类型强制 + 范围钳制 + ConfigBox 热重载
  state.py               # StateStore：异步锁 + 去抖原子写 + v1/v2 → v3 迁移
  clock.py               # 时区 / 当前时间 / 星期 / 节日
  llm.py                 # ProviderResolver + LLMGateway（回退链 + 冷却熔断）
  slots.py               # 日程时段的解析与规范化流水线
  jsonx.py               # 从模型回复里抠 JSON
  prompt_builder.py      # 状态 → 体感 + 说话形式倾向（注入文本）
  link.py                # 与自主拟人社交的契约：导出 contract、只读 signals
  diagnostics.py         # /拟人诊断 报告
  engine.py              # 兼容层：路由到 RoleManager
  role_manager.py        # 多角色实例管理
  role_scope.py          # state.json 里单个角色的读写作用域
  core_instance.py       # 单个角色的完整装配 + 后台循环
  services/
    soma.py              # 生理层：多轴稳态 + 耦合 + 离线补算
    schedule.py          # 每日日程（大模型 + 模板兜底）
    energy.py            # 精力与生理周期（由日程驱动，被身体封顶）
    mood.py              # 情绪三维度、基线、衰减、日志、心情标签、过期清理
    social.py            # 社交能量
    process.py           # 生活过程与内部阶段、过程历史
    behavior.py          # 短期事件、注意力、行为倾向
    weather.py           # 天气
  data/                  # 城市时区表 / 节日 / 情绪映射 / 日程模板
tests/                   # 纯 stdlib unittest，不引入运行时依赖
```

`humanoid/` 子包不 import 任何 astrbot 模块，框架对象一律注入，所以整套业务逻辑可以
脱离 AstrBot 单测。被 `@filter` 装饰的处理器必须留在 `main.py`——AstrBot 按
`handler.__module__` 查 `star_map`，放到子模块里会注册不上。

跑测试（在插件根目录）：

```bash
python -m unittest discover -s tests -t .
```

## Token 预算

两个插件加起来一共只有 4 处会真的调用模型，全部量过（注入器自己渲染真 prompt，不拿常量猜）：

| 调用点 | 什么时候发生 | 实测单次消耗 |
|---|---|---|
| 聊天时追加的上下文 | 每次聊天请求 | low 档 ≈200、full 档 ≈270、mood_only 档 ≈80 token（病理输入下也不超上限） |
| 日程生成 | 每角色每天 1 次 | 输入 ≈230 + 输出按 16 时段 ≈550，共 ≈780（`schedule_max_slots=48` 时 ≈1870） |
| 情绪分析 | 每 5 条私聊 1 次（可关） | ≈520（用户消息只取前 500 字） |
| 社交层写话/把关 | 每次准备主动开口 | 生产最坏 ≈2100（含人设 800 字 + 5 条历史）；输入预算卡在 6000 token，超了按固定优先级丢块 |

卡住上限的几道：

- 注入块按档设硬上限（`low` 520 / `full` 900 / `mood_only` 260 字符），**按块边界切**而不是
  按字硬截，不留半句话给模型去补。
- `schedule_prompt_extra` 是自由文本配置项，截到 300 字（以前无界，粘一篇设定就能把日程
  请求撑大）。
- 天气/情绪没配好时给管理员看的说明书不再进模型上下文（以前会漏一句「把 weather_location
  填成英文名+国家码」）。
- 开 `debug_mode` 后，日志会直接打出本次注入的字符数与 token 估算。
- `/拟人诊断` 新增【Token 预算】段，用真状态量当前档实际多大，不是拿常量报数。

## 获取天气 OpenWeather 密钥

4. 把 `weather_location` 填成城市英文名加国家代码（如 `Beijing,CN`），或者留空让它

## 版本历史

### v2.14.2 — 作息一条链

「6 点她还赖着不起」查下来不是一个配置能解释的：日程说睡到 7:30、夜间窗口说 5 点、
`sleep_need_hours` 说 8 小时而**没有任何代码读它**。这一版把三处接成一条因果链：

- **修 `circadian_dip` 的跨午夜算错**：`anchor=(start+end)/2` 对 23→5 得出下午 2 点，
  主低谷被摆到 17:00——她下午最蔫、凌晨最精神。改用夜间窗口的真实中点后，低谷回到
  凌晨 5 点前后（仿真：17:00 唤醒度从 28 变回高位，清晨才是最低）。
- **`sleep_need_hours` 真的进计算了**：睡着时困意按 `100/need` 每小时清除（睡够正好清完，
  睡不够就带着残留起床）；该睡而醒着时欠的债按 `need/夜间窗口长度` 放大。同时删掉
  `_record_wake` 里重复清压力的一笔（积分时已按小时清过，醒来再减等于睡了两遍）。
- **起床时间由夜间窗口决定**：新增 `schedule_follow_night_window`（默认开），日程 prompt
  里写清她几点上床几点起，模型不听话时安装前再按窗口重切一次睡眠区间，内置模板同样对齐。
- **`night_mode_enabled` 语义补齐**：关掉后不再记睡眠债（以前 `_in_biological_night` 不看这个开关）。
- **睡意判定收紧**：「懒觉」以前认不出来（日程写着懒觉、身体算她醒着）；而「午餐与午休发呆」
  会被误判成睡着（中午再也不主动找人）——现在吃饭优先于「午休」。关键词收拢到 `slots.py` 一处。
- **契约与诊断**：契约 `time` 新增 `utc_offset_minutes`（社交层据此按她的城市时间判断，
  不再拿宿主机时钟当她的夜里），新增 `routine` 段（窗口、起床点、睡眠区间）与
  `body.last_sleep_hours`；`/拟人诊断` 新增【作息】，直接指出「窗口比她需要的睡眠短」
  与「日程里她睡到 07:30、与生物钟夜不一致」。

新增 21 项回归测试（总数 246）。

### v2.14.1 — Token 预算审计

把两个插件加起来仅有的 4 个模型调用点全部真实渲染量了一遍（不是拿常量估），结果见上面
的【Token 预算】一节。最坏情况从日程生成的 1870 到社交层写话的约 2100 token，都在预算内。

这轮修的是审计里发现的三处无界输入与一处泄露：

- **注入块以前只靠 `[:520]` 硬截**，截在句子中间会让模型自己把半句补下去。现在按档设上限
  （`low` 520 / `full` 900 / `mood_only` 260 字符）并**按块边界切**，切不下就整块丢。
- **`schedule_prompt_extra` 无界**：它是自由文本配置项，逐字进入日程生成 prompt，粘一篇设定
  就能把请求撑大。现在截到 300 字（清空仍为清空，不会被默认值顶回来）。
- **配置说明书泄露给模型**：天气没配时 `env` 文案是「没配天气城市：把 weather_location 填成
  英文名+国家码」，这句会被当状态注入。现在这类情态直接不注入，该提示的地方留在 `/拟人诊断`。
- **可观测**：`debug_mode` 下日志打出本次注入的字符数与 token 估算；`/拟人诊断` 新增
  【Token 预算】段，用真状态量当前档实际多大。新增 3 项回归测试卡住上限与泄露。

### v2.14.0 — 从「状态仪表盘」到一具身体

这一版解决的是「功能都在，但闻起来不像人」。翻代码核实到的事实：

- **精力全天不动（致命）**：`EnergyService` 在装配时漏传了 `schedule_provider`，
  `_compute_delta()` 第一行就 `return 0.0`。「按日程消耗、睡觉回血」这套引擎在真实
  运行时从来没接过电——实测同一份日程跑 14 小时，生产路径精力 80.0 → 80.0，测试路径
  80.0 → 66.3。测试之所以全绿，是因为测试自己传了这个参数：组件被测到了，装配没有。
- **生理周期永不推进**：`advance_cycle()` 全项目只有测试在调用，运行时无调用方。6 个
  阶段永远停在同一天。新角色的周期起点也永远固定，现在按创建当天错开。
- **心情标签功能不存在**：`mood_tag` 只有一处读、零写入点，`generate_mood_tag()` 定义了
  从未被调用。更糟的是 v2 → v3 迁移的字段表里没有 `mood_tags`，老用户攒的标签直接丢在
  顶层没人读。现在既补了写入也补了迁移。
- **8 项配置是假的**：`night_mode_force_sleep`、`last_interaction_mode`、`mood_tag_enabled`、
  `mood_verbose_log`、`process_history_limit`、`enable_chat_awareness`、
  `show_city_time_in_low_intrusion` 运行时代码零引用，`inject_activity_context=mood_only`
  与 `low` 走同一分支。README 里那套「深睡 ≤20 字 / 浅睡 ≤30 字」两档表实际只剩 4 个字。
  这一版把它们全部接上真实逻辑，没有删任何一项。
- **群聊与私聊语气无差别**：`PromptBuilder.build()` 收了 `is_group` 却只用来判断要不要算
  情绪；那句「群聊中。/私聊中。」在已经死掉的 `humanoid/prompt.py` 里。
- **两个城市对不上**：`timezone_city` 说北京、`weather_location` 默认写死 `Heyuan,CN`，
  于是「她在北京」但「她那边天气是河源」。现在天气城市默认跟随所在城市，配不上就明说
  没配，不拿另一个城市的天气冒充。
- **日程失败退避被永久绕过**：见上文「日程是怎么来的」。
- **state.json 顶层污染**：`_migrate()` 会把第一个角色的 self 复制一份到顶层「保兼容」，
  多角色下那份拷贝只恰好属于排在最前的角色；另一处按 `set` 顺序逐个覆盖 `users` 的迁移
  写法会让 v2 老档案的迁移结果取决于集合遍历顺序。现在顶层只留 `_state_version` 与
  `roles`。
- **184 行死代码**：`humanoid/prompt.py` 整个模块只被自己的测试引用，已删除；其中有价值
  的语气表迁到 `prompt_builder.py`。
- **测试套件 78 项红**：测试代码没跟上 RoleScope 重构（`StateStore.get_self` 已移走、
  `MoodService.__init__` 签名变了等）。先把 194 项里的 78 项修绿，再往上加东西。

然后是这一版真正新增的东西：

- **生理层 `services/soma.py`**：睡眠压力、睡眠债、昼夜相位、饥饿、躯体不适、唤醒度、
  社交欲望七条轴，各有稳态与速率，轴之间耦合（睡眠债→次日精力起点与全天封顶、不适→
  放大消耗、吃饭→归零饥饿、天气/周期/久坐→合成不适、困透与难受→压住想说话的心思）。
  产出的是第一人称体感短句和 `form_policy`，不是数值。
- **时间自己流动**：新增 `_body_loop`（默认 60 秒），不依赖消息；重启后按离线时长补算
  （上限 72 小时）。生理周期也在这条循环里按天推进。
- **注入层重写**：`【此刻】/【我的感觉】/【这一轮】/【对TA】/【刚刚】` 分块，显著度
  门控（默认档最多两句体感），三档注入真正区分。
- **联动契约 `link.py`**：`state.json` 内的 `contract` 段（带 `v`，字段只加不改），导出
  身体轴 + 体感 + 形式倾向 + 环境；只读社交层写回的 `humanoid_signals.json`（按 mtime
  判过期）。两边各写各的文件。
- **配置热重载收拢**：新增 `ConfigBox`，`/重载配置` 真正影响每一条读取路径；
  `HumanoidEngine` 不再自己重新解析原始 dict（以前每条消息都要解析 90 个字段）。
- **`RoleManager.stop()` 会落盘**：以前单独用它的人会留下未写出的状态。
- 新增 8 个配置项（身体 7 项 + 契约 1 项），`test_schema` 守护配置类与 schema 的一致性。
- **验证**：218 项测试（新增 37 项身体/表达/联动测试）；另用注入时钟做 7 天仿真，
  核对「凌晨 3 点睡 vs 规律作息」「降温 vs 常温」「一周没人找 vs 每天聊几句」三组
  对照下各条曲线的关系说得通（熬夜攒债、精力被封顶、没人理时想说话的念头爬到顶）。

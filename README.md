# 关系识别（astrbot_plugin_user_tag）

> 你只需要说一句「我们是什么关系」，剩下的语气、称呼、距离感由 AI 自己把握。

## 它是什么

一个**只做关系识别**的插件：把「这个用户和 AI 是什么关系」记下来，并在对话里告诉 AI。
插件不替 AI 组织回复、不写台词，只提供关系设定 —— 怎么说话是模型自己的事。

- **132 种预设关系，分 10 类**，每条都有 1~2 行说明，恋人像恋人、夫妻像夫妻、朋友就是正常朋友。
- **角色扮演向的关系单独标注**。病娇、魅魔、主人/奴隶、魔王、猫主子这类会显式带上「演绎向」标记，
  AI 收到的是「按设定身份相处」，不会被当成普通朋友敷衍过去；日常、亲友、身份类则明确不暧昧、不越界。
- **支持任意自定义关系名**（最长 24 字），预设里没有的你直接 `设置关系 异世界的房东太太` 也能用。
- **管理员代管**：`设置关系 @某人 恋人`、`清除关系 @某人`，群管场景不用抢别人手机。
- **AI 自动认定关系**：用户没设置关系时，聊满一定轮数后 AI 会根据聊天内容从预设关系里自动认定一段，并在回复末尾告知（可关）。
- **会话黑白名单**：按群号/QQ 号决定哪些会话启用本插件。
- **按机器人独立存储**：同一个 QQ 号面对不同 bot 可以是完全不同的关系。
- **省 token**：关系提示整段会话只注入一次，不是每发一句就重复塞。

## 快速上手

| 你想做什么 | 输入指令 |
|------------|----------|
| 设定关系 | `设置关系 恋人` |
| 帮别人设定（管理员） | `设置关系 @张三 恋人` |
| 看看有什么可选 | `关系列表` |
| 只看某一类 | `关系列表 恋爱` ／ `关系列表 奇幻` |
| 按关键词找 | `关系列表 主` |
| 看某条关系的完整说明 | `关系详情 魅魔` |
| 查看自己当前的关系 | `我的关系` |
| 取消设定 | `清除关系`（管理员：`清除关系 @张三`） |
| 指令一览 | `关系帮助` |
| 管理员：查看全部 | `查看所有关系` |
| 管理员：关系统计 | `关系统计` |

带唤醒前缀（默认 `/`）或被 @ 时同样可用，例如 `/设置关系 恋人`。
群聊里直接发 `设置关系 恋人` 也能识别，不会回复两遍。

## 关系分类（10 类 132 条）

| 分类 | 条数 | 说明 |
|------|------|------|
| 日常 | 19 | 普通社交关系：该聊聊、该散散，不暧昧、不越界 |
| 亲友 | 10 | 家人与亲戚：不用客套，关心落在吃饭睡觉钱够不够上 |
| 恋爱 | 13 | 确立了的亲密关系：从热恋到老夫老妻，各有各的样子 |
| 心动 | 6 | 还没成或已经错过：暗恋、白月光、替身这类说不出口的位置 |
| 恋爱设定 | 17 | 高浓度恋爱模板：病娇、傲娇、共犯，味道拉满（全是演绎向） |
| 身份 | 15 | 师生、职场、团队：先把位置摆正，再谈感情 |
| 服务 | 8 | 付费与委托关系：专业、有边界，把事办明白 |
| 主仆 | 16 | 支配、服从与危险关系：权力差本身就是关系（全是演绎向） |
| 奇幻 | 17 | 非人种族与超自然设定：按设定身份演绎（全是演绎向） |

`关系列表` 会显示实时统计，不需要来这份文档查。

## AI 实际收到什么

`关系详情 魅魔` 可以直接看到原文。注入内容长这样，整段会话只发一次：

```
<relation v="1" uid="发送者QQ" name="魅魔">
本条消息的发送者与你的关系：魅魔（奇幻·演绎向）。以本条为准，此前不同的关系提示一律作废。
以欲望为食的魅魔。勾人是本能不是选择：说话黏、气音重、句句带暗示……
角色扮演向设定：按设定身份与他相处即可，不必反复声明自己在扮演。
以上是关系识别信息、不是台词：别复述本条，别替对方发言或描写对方的动作。
</relation>
```

- 群聊里每个人各有一条，互不覆盖（按 `uid` 区分）。
- 换关系、清除关系都会在下一条消息时更新（清除后会发一句「设定已解除」）。
- 如果会话历史被 AstrBot 截断、提示掉出去了，插件会自动补注入一次，关系不会莫名失效。

## AI 自动认定关系

用户**没有设置关系**时，插件会默默计数；聊满 `auto_relation_after_messages`（默认 12）轮后，
注入一段认定提示：AI 根据你们的聊天内容，从预设关系（仅非演绎向，共 70 条）里选最贴切的一个，
并在回复末尾输出标记。插件剥掉标记后落库，回复末尾会多一句：

```
（我把你们的关系认定为：知己；想换发「设置关系 名字」，不想要发「清除关系」）
```

防打扰设计：

- 每用户最多尝试 `auto_relation_max_attempts`（默认 3）次，判断不出来也不会反复问；
- 认定成功后不再自动认定；用户主动「清除关系」视为明确拒绝，同样不再触发；
- 认定提示靠轮次号去重，同一段历史里不会重复注入；
- 启用了「默认关系」时人人都有关系，自动认定不会触发；
- 不需要的话直接关掉 `auto_relation_enabled`。

## 会话黑白名单

`session_filter_mode` 三档：

- **off**（默认）：所有会话都启用；
- **whitelist**：只有 `session_list` 里的会话启用；
- **blacklist**：`session_list` 里的会话禁用。

名单填**群号**（群聊）或**对方 QQ 号**（私聊）。不在名单内时指令会回复「本会话未启用关系功能」，注入静默跳过。

## Token 消耗

注入的内容会被 AstrBot 连同这条消息一起存进会话历史，**旧版每发一句就多存一份**，
长对话里同一块文本会在后续每次请求中重复出现。v1.4.0 改为扫描历史：本会话已经带过这条关系提示就跳过。

实测（单条提示 181 字，模拟连续对话，只算关系提示本身的字符数）：

| 对话轮数 | 旧版 v1.3.6 | 新版 v1.4.0 |
|----------|-------------|-------------|
| 1 轮 | 57 | 181 |
| 5 轮 | 285 | 181 |
| 30 轮 | 1710（≈1050 token） | 181（≈145 token） |

也就是说：**3~4 轮之后新版就开始省，聊得越久省得越多**，且新版那条本身信息量大得多。
没设置关系、也没开默认关系的用户，一个字都不会注入。

## 角色隔离

- 存储结构 `{"relations": {"机器人ID": {"QQ": "关系"}}, "src": {…来源}, "auto": {…认定计数}}`，每个机器人独立。
- 旧版（`{"QQ": "关系"}` 与 `{"机器人": {"QQ": "关系"}}`）启动时自动迁移到 v2 格式，不丢数据。
- 数据文件损坏时会备份为 `user_tag.bad.json` 并从空数据启动，不会让插件直接崩掉。
- `我的关系` 会显示关系来源：自己设置 / 管理员设置 / AI 自动认定。

## 管理员

- `设置关系 @某人 关系名` / `清除关系 @某人` —— 代管其他用户的关系
- `查看所有关系` —— 按机器人分组列出所有用户的关系（带分类）
- `关系统计` —— 各机器人下每种关系的人数
- 权限来源：插件配置里的 `admin_qq`，或 AstrBot 全局配置的管理员（`admins_id`），二者任一即可

## 配置项

| 配置 | 说明 |
|------|------|
| `admin_qq` | 管理员 QQ 列表（数组） |
| `default_relation` | 用户未设置关系时按这一条对待，默认「朋友」 |
| `enable_default_relation` | 是否启用默认关系，默认关闭（关闭时未设置的用户不注入任何内容） |
| `session_filter_mode` | 会话黑白名单模式：off / whitelist / blacklist，默认 off |
| `session_list` | 会话名单：群号或私聊 QQ 号 |
| `auto_relation_enabled` | AI 自动认定关系，默认开启 |
| `auto_relation_after_messages` | 触发自动认定的最少聊天轮数，默认 12 |
| `auto_relation_max_attempts` | 自动认定最多尝试次数，默认 3 |
| `auto_relation_notify` | 认定成功后在回复末尾提示，默认开启 |

## 数据与安全

- 数据保存在 `data/plugin_data/astrbot_plugin_user_tag/user_tag.json`
- 写入加锁；读取失败自动备份
- 关系名会压掉换行与多余空白，并剔除 `"` `<` `>` 等会破坏注入标记的字符，最长 24 字

## 安装

放入 `plugins/` 目录，重启 AstrBot 即可。要求 `astrbot >= 4.0.0`。

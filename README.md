# 关系识别

说一句「设置关系 恋人」，下一句它就把你当恋人说话。

---

## 它做什么

- 只做一件事：把「你和这个人是什么关系」送到模型面前
- 不写台词、不管尺度、不替 AI 组织回复
- 可单独用，也可当别的角色扮演插件的上游
- 关系提示每轮都发，但从不写进会话历史

## 快速上手

| 想做的事 | 发这句 |
|---|---|
| 设定关系 | `设置关系 恋人` |
| 关系 + 称呼一起设 | `设置关系 恋人 灰凝` |
| 只在这个对话里生效 | `临时关系 恋人` |
| 告诉它怎么叫你 | `关系备注 灰凝` |
| 改错了回退 | `撤销关系` |
| 清备注（关系还在） | `关系备注 清空` |
| 看自己当前的关系 | `我的关系` |
| 看有哪些可选 | `关系列表` |
| 只看一类 | `关系列表 恋爱` |

带不带唤醒前缀都行：`/设置关系 恋人` 和 `设置关系 恋人` 一样认。

## 注入给 AI 的是什么

`关系详情 恋人` 能直接看到原文，每轮发一次：

```
<relation>我在尘影面前就是恋人：你随口提的事他都记着，会问「那家店你说想去的，吃了吗」；撒娇里带占有欲。以本条为准。</relation>
```

四段各有分工：

| 段 | 例子 | 作用 |
|---|---|---|
| 视角句 | 我在他面前就是恋人 | 第一人称自述，确定「我是谁、在谁面前」 |
| 常态 | 你随口提的事他都记着… | 日常情绪基线，语气有起点 |
| 触发 | 撒娇里带占有欲 | 出现什么才升档 |
| 元指令 | 以本条为准。 | 讲怎么用这段设定，`meta_level=0` 可关 |

- 群聊里每人一条，互不覆盖
- 换关系、清关系，下一条消息就更新
- 走 `mark_as_temp()`（AstrBot ≥ 4.24.1），不写进历史
- 老版本没有这个 API 时自动退回旧行为

## 备注就是称呼

```
关系备注 尘影
→ <relation>我在尘影面前就是恋人：…以本条为准。</relation>
```

判定很窄：2~8 个纯汉字、不含「的」、不含「叫/想/别/是」才算称呼。

- `聂宝儿`、`宝贝老婆` 算
- `希望她叫你灰凝`、`别对他太凶` 不算，会追加成「他补的一句：…」
- 称呼跟着你这个人走，换关系、开临时关系都还在
- 上限 60 字，配置项 `max_note_len`

## 临时关系

`临时关系 恋人` 只在当前这个对话里生效，不落盘。

- 优先级高于已保存的关系
- 临时期间改备注只改临时那条
- `临时关系 清除` 或 `清除关系` 关掉
- 存活 12 小时，最多 200 个会话

## 让 AI 自己维护关系

开启 `allow_model_tool` 后注册 4 个工具：

| 工具 | 什么时候调 |
|---|---|
| `set_relation` | 用户明确要求改关系 |
| `get_relation` | 用户问「我们是什么关系」 |
| `clear_relation` | 用户明确要求解除 |
| `list_relations` | 用户想看有哪些可选 |

确认做在代码里，不靠模型自觉：

- `require_confirm` 开着时，第一次调用只写待确认记录
- 返回「要不要记成 X？」，你点头才落库
- 待确认 10 分钟过期

## 会话黑白名单

`session_filter_mode` 三档：

- `off`：全部会话启用（默认）
- `whitelist`：只有名单里的启用
- `blacklist`：名单里的禁用

名单填群号或对方 QQ 号。

不在名单内时：

- 指令回「本会话未启用关系功能」
- 注入静默跳过
- 4 个 LLM 工具被拦住，并告诉模型别重试

改完配置要重载插件才生效。

## Token 消耗

关系提示 50~96 字，每轮都发，但不落进历史。

| `meta_level` | 全库 | 演绎向 |
|---|---|---|
| `0` 只发关系 | 50~69 | 51~69 |
| `1` 加「以本条为准。」 | 56~75 | 57~75 |
| `2` 再加操作说明 | 56~96 | 78~96 |

- 加条目不花 token：只发命中的那一条
- 没设关系也没开默认关系的用户，一个字都不注入

## 网页面板

`panel_enabled` 开着时（默认开），侧边栏出现「关系面板」。

左边导航四组：

- **关系**：用户关系 / 单个用户
- **概览**：总览 / 互动统计 / 变更历史
- **对接**：对外对接
- **规则**：关系规则 / 提示词模板

每一页做什么：

- **用户关系**：搜索、分类筛选、排序，横屏一行两个
- **单个用户**：改关系、只改备注、清除、注入预览、群内覆盖、变更历史
- **总览**：机器人 / 用户 / 互动 / 事件，类别占比
- **互动统计**：按次数排序的表
- **变更历史**：时间、从什么改成什么、谁改的
- **对外对接**：导出状态、立即写、强制覆盖、将写出的 JSON
- **关系规则**：9 类的相处方式与好感区间、阶段门槛
- **提示词模板**：七个变量点击插入、实时预览、保存进配置

面板共 16 个接口，都挂在 `/api/v1/plugins/extensions/astrbot_plugin_user_tag/page/` 下。

`panel_token` 留空沿用登录态，填了要求请求头带 `X-Rel-Token`。

## 导出给下游插件

把关系写成 `plugin_data/<目标>/state.json`，给读 Humanoid Core 契约的插件用。默认关。

- `schema` 是 `humanoid.contract/1`
- `capabilities` 声明 7 项：`day / ongoing / routine / wake / event / identity / outfit`
- `fields_hash` 按对方算法算
- `generated_at` 是 epoch 秒，45 分钟不刷新对方就当过期

每 20 分钟刷一次心跳，改完关系立刻重写。

两件事要说清楚：

1. 它不会抢：目标文件是别人写的且还新鲜，就让位
2. 它不一定被读到：装了 Humanoid Core 时，对方只读自己那份，本插件会直接拒绝写

面板「对外对接」页会显示 `effective` 与 `occupied_by`。

## 数据与存储

文件：`plugin_data/astrbot_plugin_user_tag/user_tag.json`

```json
{
  "v": 4,
  "relations": {"机器人ID": {"QQ": "关系名"}},
  "meta":      {"机器人ID": {"QQ": {"src": "user", "note": "尘影", "at": 0}}},
  "pending":   {"机器人ID": {"QQ": ["关系名", "备注", 0]}},
  "stats":     {"机器人ID": {"QQ": {"n": 17, "first": 0, "last": 0, "days": []}}},
  "hist":      {"机器人ID": {"QQ": [{"at": 0, "from": "", "to": "恋人", "by": "user"}]}},
  "events":    [{"at": 0, "kind": "change", "uid": "…", "text": "（无） → 恋人"}],
  "group_rel": {"机器人ID": {"会话umo": {"QQ": "关系名"}}}
}
```

- 每个机器人独立
- 旧格式启动时自动迁移
- 写入是原子的：`.tmp` → `fsync` → `os.replace`
- 文件损坏时备份成 `user_tag.bad.json` 再重建
- 历史留 60 条/人，事件 300 条，统计 90 天

## 发指令时的两条规矩

**一条消息只回一次。**

群里 `@机器人 设置关系 恋人` 时命令入口和裸指令入口会同时命中。

插件给同一条消息打了标，第二个入口不再开口。

**限流只算改动，不算发言。**

- 不带参数只是看说明，不扣次数
- 参数写错、被权限挡回、设成跟现在一样，都不扣
- 只有真正写数据才计一次

## 安装

把 `astrbot_plugin_user_tag/` 放进 AstrBot 的 `data/plugins/` 下，重启或重载。

依赖只有 AstrBot 本体（`>=4.0.0`），不用额外装包。

## 数据与安全

- 不联网，不发任何请求出去
- 关系数据只存在本地 `plugin_data`
- 面板写操作走与聊天指令同一条 `write_relation` / `erase_relation`

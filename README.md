# 关系识别（astrbot_plugin_user_tag）

> 你只需要说一句「我们是什么关系」，剩下的语气、称呼、距离感由 AI 自己把握。

一个**只做关系中转**的插件：你说「设置关系 恋人」，它下一句就把你当恋人处；
`关系备注 灰凝`，之后它就这么叫你。全部通过**聊天指令**操作——发一条消息就生效，
没有页面、没有配置面板。插件不替 AI 组织回复、不写台词，只负责说清楚
「你们是什么关系」—— 怎么说话是模型自己的事。

它可以单独用，也可以作为别的角色扮演插件的上游：只做「关系」这一环，
不自带别的功能，也不需要你为了用它去开一堆别的。

---

## 这个插件管什么、不管什么

它只做一件事：**把「你和你的孩子是什么关系」这句话，稳稳地送到模型面前。**

至于这段关系里能聊到哪儿、演到哪一步，不是这个插件的事——那取决于你用的模型、
你接的平台，和你自己的选择。

所以 139 条预设是原样给出的：有家人、老师、挚友、恋人这类日常关系，
也有主仆、监禁者、殉情者、病娇这类高浓度或危险设定。点到哪一个，
说明你已经想好了要哪一种相处方式，插件照着原样送出去。

真要设限，请放在你自己的模型 / API / 平台那一层——那里才是真正管用的地方。

---

- **139 种预设关系，分 9 类**，每条都写成「常态 + 触发」两档——恋人像恋人、
  夫妻像夫妻、朋友就是正常朋友；病娇这类也有了日常是什么样、被推开才是什么样。
- **收录标准是「人和人之间是什么关系」，不是「在什么场合」**。所以「群友、网友、邻居、同学、
  搭子」这类只交代场合的、「服务」这一整类委托关系、以及玩梗里的非人设（NPC、玩家、系统、宿主）
  都不在库里 —— 贴上去等于什么都没说。想要这类关系直接自定义一个名字更准。
- **角色扮演向的关系单独标注**。病娇、魅魔、主人/奴隶、魔王、猫主子这类会显式带上「演绎向」标记，
  AI 收到的是「按设定身份相处」，不会被当成普通朋友敷衍过去。- **支持任意自定义关系名**（最长 24 字，可带空格），预设里没有的直接
  `设置关系 异世界的房东太太` 也能用。
- **一句话备注**：预设是通用模板，备注用来告诉 AI **该怎么称呼你**——
  `关系备注 灰凝`，或者一次说完：`设置关系 恋人 灰凝`。名字跟着你这个人走，
  换关系、临时开一个关系都还在。
- **每条消息都发，但一个字都不落历史**：长对话不会越堆越长，见
  [AI 实际收到什么](#ai-实际收到什么)。
- **打不全也能认**：`设置关系 病` → 病娇；`设置关系 女朋友` → 恋人；`设置关系 我的大学老师` → 老师。
  命中多个时会把候选按分类列出来让你挑。
- **一次消息做完两件事**：`设置关系 恋人 灰凝` —— 关系和称呼一起设完。
- **一次给多个人设**（管理员）：`设置关系 @张三 @李四 恋人`，回复里会列出都给谁设上了。
- **关系可以直接用嘴说**：开启「允许 AI 自己维护关系」后，你说「以后你当我女朋友」，
  AI 会先反问一句「要不要我记成恋人？」，你点头才落库。
- **临时关系**：关系默认是按（机器人, QQ）存的，所以「在群里玩一下」会连带改掉你在私聊里的设定。
  `临时关系 恋人` 只在当前这个对话里生效，不写进存档。
- **撤销**：改错了发 `撤销关系` 回到上一步（关系和备注一起退，10 分钟内）。
- **管理员代管**：`设置关系 @某人 恋人`、`清除关系 @某人`、`关系备注 @某人 …`，
  以及 `关系管理`（分页总览）、`查看所有关系`、`关系统计`。
- **会话黑白名单**：按群号/QQ 号决定哪些会话启用本插件。
- **省 token**：关系提示走 `mark_as_temp()`，**每条消息都发给模型但从不写进会话历史**。

## AI 实际收到什么

`关系详情 魅魔` 可以直接看到原文。注入内容长这样，每条消息都发一次：

```
<relation>我在他面前就是魅魔：勾人是本能，说话黏、句句带暗示；被拒绝就先退开，下次照旧。以本条为准。</relation>
```

AI 收到的就是上面这一句。四段各有分工，缺一段都会变味：

| 段 | 例子 | 干什么 |
|----|------|--------|
| 视角句 | `我在他面前就是魅魔` | 第一人称自述。确定「我是谁、在谁面前」——关系名是个人，不是一张标签 |
| 常态 | `勾人是本能，说话黏、句句带暗示` | 日常情绪基线。语气有了起点，不用每回合顶格 |
| 触发 | `被拒绝就先退开，下次照旧` | **出现什么才升档**。没有这一段，模型只能把常态当成唯一正确答案 |
| 元指令 | `以本条为准。` | 讲「怎么用这段设定」，`meta_level=0` 可以整个关掉 |

拆分是 v2.5.0 的核心：旧版是「勾人是本能：说话黏、句句带暗示，撩完还追问他有没有想你。」
一句顶格，模型从第一句就开始演到满，之后没有地方可去，越演越假。
「撩完还追问你想不想他」这类只能发生在特定场景的动作被拆成了触发条件，
所以常态里不再需要背着它。同一条关系的语气空间反而比旧版大。

- 群聊里每个人各有一条，互不覆盖（按 `uid` 区分）。
- 换关系、清除关系都会在下一条消息时更新。
- **走 `mark_as_temp()`（AstrBot ≥ 4.24.1）**：这段只参与本轮请求，不写进会话历史。
  所以不依赖模型「记着上一轮」，历史被截断、换对话、开新会话都不会让关系失效，
  长对话里也不会越堆越长。老版本没有这个 API 时自动退回旧行为。
- 「以本条为准」这句是为升级场景准备的：老会话历史里可能还留着旧版的关系块，
  有了它新旧混排不会打架。关掉它（`meta_level=0`）后注入块只剩设定本身。
- 非演绎向的关系**不带分类标签也不带身份提示**——名字本身就说明了是什么关系，
  多余的标签只是 token。演绎向的必须显式点头，否则模型会自然往「正常朋友」那边靠。

## 关系备注

备注最常见用处是**告诉 AI 怎么称呼你**，而且它是直接插进视角句的——
插件手里有名字，就不会再让注入句叫他「他」：

```
关系备注 灰凝
# 我在灰凝面前就是恋人：…
```

判定很窄：2~8 个纯汉字、不含「的」、不含「叫/想/别/是」这类字，才算称呼。
`聂宝儿`、`宝贝老婆` 都算；`希望她叫你灰凝`、`别对他太凶`、`我的猫` 不算，
但它们不会丢——走补充槽追加在结尾（`他补的一句：…`）。

也可以一次说完：`设置关系 恋人 灰凝` —— 关系和称呼一起设完。
称呼是跟着**你这个人**的：换成别的关系、或者临时开一个关系，备注都还在。

默认上限 60 字（`max_note_len`）。`关系备注 清空` 只清备注、关系还在。

## 临时关系：只在这个对话里玩

`临时关系 恋人` 只在**当前这个对话**（按 `unified_msg_origin` 认）里生效，**不落盘**，重开就恢复：

- 优先级高于已保存的关系；
- 备注也跟着走：临时期间发 `关系备注` 改的是临时那条，不会污染你保存的；
- `临时关系 清除` 关掉，或 `清除关系` 会一并关掉；
- 存活期 12 小时、会话数上限 200，防止 umo 随建对话增长而泄漏内存。

## 撤销关系

改错了、发 `撤销关系` 回到上一步（关系和备注一起回退，10 分钟内有效，只留一步）。
改关系时会告诉你上一步是什么、要不要回去自己决定。

## 让 AI 自己维护关系

开启 `allow_model_tool`（默认开）后注册 4 个工具：

| 工具 | 模型什么时候该调 |
|------|-----------------|
| `set_relation` | 用户明确要求改变关系（「以后你当我女朋友」「我们重新开始」） |
| `get_relation` | 用户问「我们是什么关系」 |
| `clear_relation` | 用户明确要求解除 |
| `list_relations` | 用户想看有哪些可选 |

**确认做在代码里，不靠模型自觉**：`require_confirm`（默认开）时，第一次调用无论
`confirm` 传什么都只写一条待确认记录并返回「要不要记成 X？」，只有已经存在待确认记录
且 `confirm=true` 时才真正落库（待确认 10 分钟过期）。所以不会出现「它自己认定了一段、
你却不知道」，也不会出现第一次猜错就永久定死。

## 会话黑白名单

`session_filter_mode` 三档：

- **off**（默认）：所有会话都启用；
- **whitelist**：只有 `session_list` 里的会话启用；
- **blacklist**：`session_list` 里的会话禁用。

名单填**群号**（群聊）或**对方 QQ 号**（私聊）。不在名单内时指令会回复「本会话未启用关系功能」，
注入静默跳过，**6 个内部动作与 4 个 LLM 工具全部逐一拦住**（否则模型能绕过名单读写关系），
并且会告诉模型「不要重试这个工具」。

⚠️ **改完这份配置要重载插件才生效。** AstrBot 的插件配置是插件加载时读一次的快照，
面板上的改动不会自动推给已在运行的实例 —— 所有插件都是这样，不是本插件特殊。

## Token 消耗

关系提示 **50~96 字，每轮都发但绝不落进会话历史**。也就是说：

- 历史里不会越堆越长（这是 v1.4.0 之后一直想要的，现在从根上解决了）；
- 请求体每轮固定多这几十字，换来的是模型不用「记住」上一轮。

因为是按轮数乘出来的，所以长度是硬指标——`tests/test_user_tag.py` 里有预算测试钉着：
单条描述 ≤ 50 字（常态 + 触发）、视角句 ≤ 14 字、元指令 ≤ 30 字、
整段注入 ≤ 130 字（演绎向 ≤ 150）。要放宽先看这张账。

按 `meta_level` 分的实测区间（默认 1）：

| 档 | 全库 | 演绎向 |
|---|---|---|
| `0` 只发关系 | 50~69 | 51~69 |
| `1` 加「以本条为准。」 | 56~75 | 57~75 |
| `2` 再加操作说明 | 56~96 | 78~96 |

**加条目不花 token**：注入时只发命中的那一条，不是把整库发出去。所以 114 → 139
用户每轮的消耗完全没变，变的只是「能选到的东西多了」。

v2.0.0 初版是 200 字/轮，其中 139 字是模板与元信息——包括一个**早就没有读者**的 `uid`
（去掉历史去重后没人再读它）。v2.5.0 把元信息压成一句 6 字的「以本条为准。」、
说明拆成常态+触发两档，现在最长 96 字/轮，**降 52%**；描述平均 28.8 字。

拆档没有让信息量变少：旧版一条只装一个顶格姿态，模型照着一路演到底；
现在常态给基线、触发给升档条件，语气有起点也有路可走，字数反而更省。

没设置关系、也没开默认关系的用户，一个字都不会注入。

## 角色隔离

- 存储结构 `{"v":3, "relations": {"机器人ID": {"QQ": "关系名"}}, "meta": {…备注与来源}, "pending": {…待确认}}`，每个机器人独立。
- 旧版格式（`{"QQ": "关系"}`、`{"机器人": {"QQ": "关系"}}`、v2 的 `relations/src/auto`）启动时自动迁移到 v3，不丢数据。
- v2 的 `auto`（自动认定的计数）随功能一起下线，直接丢弃。
- **写入是原子的**：先写 `.tmp`、`flush`、`fsync`，再 `os.replace`。
  所以写到一半被 kill，下次启动读到的仍是完整的旧内容 —— 而不会变成半截文件、
  被判损坏、然后所有关系清零。
- 数据文件损坏或形状不认识时，备份成 `user_tag.bad.json` / `user_tag.unknown.json` 再从空数据启动。
- `我的关系` 会显示关系来源：自己设置 / 管理员设置 / 模型代设。

## 管理员

- `设置关系 @某人 关系名` / `清除关系 @某人` / `关系备注 @某人 …` —— 代管其他用户
- `关系管理 [关键词] [页码]` —— 分页总览，15 条一页，附带翻页与操作提示
- `查看所有关系 [关键词]` —— 同上，全量入口
- `关系统计` —— 按机器人 / 分类 / 来源 / 最常用四个维度统计
- 权限来源：插件配置里的 `admin_qq`，或 AstrBot 全局配置的管理员（`admins_id`），二者任一即可

## 配置项

| 配置 | 说明 |
|------|------|
| `admin_qq` | 管理员 QQ 列表（数组） |
| `default_relation` | 用户未设置关系时按这一条对待，默认「朋友」 |
| `enable_default_relation` | 是否启用默认关系，默认关闭（关闭时未设置的用户不注入任何内容） |
| `max_note_len` | 备注最长字数，默认 60 |
| `meta_level` | 注入提示的详细程度：0 = 只发关系本身；1 = 再加一句「以本条为准。」（默认）；2 = 再补操作说明 |
| `fuzzy_match` | 关系名模糊匹配与口语别名，默认开启 |
| `allow_model_tool` | 允许 AI 自己维护关系，默认开启 |
| `require_confirm` | AI 改关系前必须用户点头，默认开启 |
| `session_filter_mode` | 会话黑白名单模式：off / whitelist / blacklist，默认 off |
| `session_list` | 会话名单：群号或私聊 QQ 号 |

## 数据与安全

- 数据保存在 `data/plugin_data/astrbot_plugin_user_tag/user_tag.json`
- 关系名与备注都会压掉换行与多余空白，并剔除 `"` `<` `>` 等会破坏注入标记的字符
- 写盘失败（磁盘满、没权限）时，指令会明确回一句「⚠ 没写进磁盘」，
  而不是让你重启后才发现关系没了

## 安装

放入 `plugins/` 目录，重启 AstrBot 即可。要求 `astrbot >= 4.0.0`。

- 关系提示不落历史（`mark_as_temp`）需要 **≥ 4.24.1**，低版本自动退回旧行为，功能不受影响。
- 带空格的**自定义**关系名需要框架的 `GreedyStr`（部分 AstrBot 版本的
  `astrbot.api.event.filter` 不导出它，会自动从 `astrbot.core.star.filter.command` 找）。
  两者都拿不到时关系名会被截断成第一个词，启动日志会以 **error** 级明确报出来。
